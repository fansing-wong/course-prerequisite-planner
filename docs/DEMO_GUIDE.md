# 演示与答辩讲解

本文按 4–6 分钟演示设计，可用网页界面快速展示，也可补充命令行运行结果。项目根目录中的 `index.html` 可直接在浏览器打开。

## 一、推荐演示流程

### 1. 先说明模型

打开网页后选择“稀疏 DAG”示例。指出每个顶点是一门课程，边 `C02 → C04` 表示 C02 是 C04 的直接先修课。独立课程没有入边，因此可以从第一学期开始。

### 2. 看拓扑顺序和并行课程

展示合法修读顺序，再观察学期安排。同一轮中所有入度为 0 的可修课程可以并行；完成这一轮后，系统删除这些课程对应的出边，继续寻找新变为可修的课程。

### 3. 展示学分上限

将每学期学分上限设为 8。课程按当前列表顺序贪心放入学期，超出上限的可修课程会延到后续学期。强调这是一个易解释的启发式规则，不承诺全局最少学期数。

### 4. 展示环路检测

选择“有环”示例。系统无法给出完整拓扑序，会定位一条闭合冲突路径：

```text
C02 → C03 → C04 → C02
```

说明只要先修图有环，就不存在能满足所有约束的修读顺序。删除或调整冲突边后，可以重新生成计划。

### 5. 展示编辑和数据交换

可添加一门课程或一条先修关系，观察图和计划刷新；再用“导出”保存文本数据，用“导入”恢复。浏览器导出的 UTF-8 文件带 BOM，C++ 程序也能读取。

若要展示命令行版本，可在项目根目录运行：

```powershell
./build/course_plan.exe ./data/sparse.txt
./build/course_plan.exe ./data/cycle.txt
```

## 二、答辩时的算法说明

### 为什么用邻接表？

先修图通常比较稀疏。邻接表只保存实际存在的关系，空间复杂度为 `O(V + E)`；遍历某门课程的后续课程时，只需访问它的出边。

### Kahn 算法怎么得到修读顺序？

1. 统计每门课的入度。
2. 把所有入度为 0 的课程放入队列。
3. 取出课程加入顺序，并将其出边指向课程的入度减一。
4. 新变为入度 0 的课程入队。
5. 若处理课程数等于总数，则得到一个合法拓扑序；否则图中有环。

时间复杂度为 `O(V + E)`。若同一轮取出所有当前入度为 0 的课程，就得到按先修层次划分的学期批次。

### 为什么检测到环后还要 DFS？

Kahn 算法能判断“有环”，但剩余未处理的顶点还可能包括受环影响的后续课程。程序在剩余子图中用 DFS 追踪访问状态和父节点，返回一条实际闭合的环路，便于用户找到冲突边。

### 学分上限是不是最优排课？

不是。当前规则按课程顺序把课程放进当学期剩余学分中，简单且可解释，但会受课程顺序影响。若需要最少学期数或满足更多现实条件，需要使用约束规划/整数规划，并增加开课学期、容量和时间冲突等数据。

## 三、核心代码索引

| 位置 | 作用 |
| --- | --- |
| `course_plan_core.hpp/.cpp` 的 `CoursePlan` | 课程、邻接表及增删改操作 |
| `CoursePlan::topologicalOrder` | Kahn 拓扑排序；若失败则用 DFS 找环 |
| `CoursePlan::buildSemesters` | 依先修层次生成学期计划，并应用学分上限 |
| `CoursePlan::load` / `save` | 读取和保存 `COURSE` / `EDGE` 文本格式 |
| `course_plan.cpp` | 命令行菜单和结果展示，不包含图算法实现 |
| `index.html` 的 `analyze()` | 网页版拓扑分析和环路定位 |
| `index.html` 的 `buildSchedule()` | 网页版学期分配 |
| `index.html` 的 `renderGraph()` | 将课程依赖绘制为 SVG 有向图 |
| `tests/course_plan_core_tests.cpp` | 核心算法、排课和文件读写的自动化测试 |

## 四、演示边界

- 当前计划只建模“先修”关系和学分上限，不处理时间表、开课学期、课程容量或毕业审核。
- 学分上限排课是贪心安排，不保证全局最优。
- 网页编辑数据保存在本地浏览器，不会自动同步到其他设备。
- CTest 覆盖 C++ 核心模型、算法和文件读写；网页交互目前仍需人工演示检查。
- GitHub Actions 会在 Windows 和 Ubuntu 上构建程序并运行 CTest。
